# playRecap · 私人听书

将自己的音频保存在服务器上，用手机或电脑打开网页听。播放时仅请求自己的服务器，不再请求 YouTube、Piped 或其他解析接口。

## 运行

需要 Python 3.10+。不需要安装后端依赖。

```sh
python3 server.py --host 0.0.0.0 --port 8765
```

Mac 也可双击 `start.command`。保持终端运行；按 Control-C 停止。

- 本机：`http://localhost:8765`
- 同一私人 Wi-Fi 下的手机：`http://Mac的局域网IP:8765`
- 首次运行自动生成访问口令，保存在 `data/access-code.txt`。输入一次后浏览器记住登录 30 天。
- 网页、书名、音频和上传接口分开处理，未登录无法读取书架和音频。网页本身只有登录入口，没有音频数据。
- Mac 必须保持开机、服务运行、网络可达。当前版本是本地/局域网服务，不等同于已经部署到公网。不要直接将 HTTP 端口暴露到公网；远程使用需要 HTTPS 反向代理或私人网络，HTTPS 代理后启用 `--secure-cookie`。

## 导入音频

打开网页，点击“导入音频”，填写书名，一次选择多个 MP3 / M4A 文件。同名章节不会被覆盖。单文件上限 2 GB。文件按自然顺序排列，建议命名 `001 - 第一章.m4a`、`002 - 第二章.m4a`。

也可以直接放文件：

```text
library/
  我的第一本书/
    001 - 第一章.m4a
    002 - 第二章.m4a
```

刷新网页书架即可出现。录音、已购可下载音频、获准使用的内容均可导入；不读取浏览器账户或 cookie。

### 从 YouTube 导入

需要当前版本 `yt-dlp`、Node.js 和 `ffmpeg`。只在导入时访问 YouTube，播放时使用下载完成的文件。

```sh
python3 import_youtube.py 'https://www.youtube.com/playlist?list=PLAYLIST_ID' --book '书名' --items '1:3'
```

默认仅下载前 3 个条目。通过 `--items '4:20'` 继续下一批；已完成项目由下载归档跳过。可用 `--downloader /path/to/yt-dlp` 指定隔离环境。下载可能因 YouTube 接口变化、视频下架、地区或访问限制失败；失败时保留已完成的文件。

## 已实现

- 持久化音频书库、批量上传、章节自然排序。
- 单个原生 audio 元素，章节接续；不会在音频错误时跳过章节。
- 进度条、前后 15 秒、倍速、每本书单独记录进度。
- 15/30/45/60 分钟睡眠定时、“本章结束”停止。
- 支持的浏览器上接入 Media Session 锁屏/耳机控制和 Audio Session。
- HTTP Range 分段读取，可在长音频中定位，无需先下载整集。
- 自适应手机布局、暗色界面、键盘可操作控件。

进度存在当前浏览器的 localStorage，不跨设备同步；清除浏览器数据会丢失进度，但服务器音频仍在。上传的文件存在服务器，不代表手机已经离线下载。

## 验证与限制

```sh
python3 -m unittest discover -s tests -v
node --check script.js
node --test tests/playback.test.cjs
```

后端测试覆盖访问控制、私人路径隔离、上传重复保护、目录穿越、符号链接、Range 和 HEAD。

手机 Safari 锁屏长播、锁屏跨章、电话打断、耳机按键、睡眠定时需用实际 iPhone 验收。网页定时器可能被操作系统延迟，已同时在音频事件和回到前台时按实际截止时间补查，但不能声称有原生 App 级别的精确定时保证。

## 原版本

本次本地副本的 `legacy/` 保存了改造前未提交的页面、脚本、样式和说明（备份不进入 Git）。原始工作目录未被修改。新旧播放器的进度命名空间不同；YouTube 旧书单及旧进度不会被删除，也不会伪装成已导入的音频。

`data/`、`library/` 中的口令和音频不进入 Git。

## 独立线上部署（手机流量可访问）

已包含 Dockerfile 和 Railway 配置，但未自动创建计费资源。

1. 从代码分支部署为独立服务，挂载持久磁盘到 `/storage`。必须挂载持久磁盘，否则重新部署会丢失音频与访问口令。
2. 启用 HTTPS 域名。容器默认启用 Secure 登录 cookie，不支持直接用明文 HTTP 登录。
3. 从服务私有文件 `/storage/auth/access-code.txt` 取得口令；不得把口令写入仓库、URL 或构建日志。
4. 登录 HTTPS 网页后上传音频。音频存在 `/storage/library`，认证资料存在 `/storage/auth`，仅需备份这一持久磁盘。
5. 手机关闭 Wi-Fi，用移动数据验证登录、播放、拖动进度和跨章，再进行锁屏半小时测试。

线上服务可在 Mac 关机时继续工作。只有网页地址公开，书架和音频仍需口令。当前播放器尚未提供手机离线缓存，没信号时不能保证继续播放。
